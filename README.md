# xlog

**주 3회 이상 숏폼을 만드는 1인 크리에이터**를 위한 도구.
Raw video(1~3개) + 자유 요청 한 줄 → AI가 핵심을 추출 → 30~60초 세로형(9:16) 숏츠 2편(A/B) 제작 → AI 심사 + **파일럿 크리에이터(당신)의 선택**으로 편집 기준을 학습하는 로컬 웹앱.

> 현재 로컬 버전의 정체성: **"내가 xlog를 만들면서 쓰는, 내가 기준을 만드는 앱."**
> 내 평가(어느 편집이 좋은지 + 이유)와 내가 주는 YouTube 레퍼런스 링크로부터 기준(rubric)이 계속 진화한다.

CutClaw(GVCLab) 분석 기반 설계 — [docs/CUTCLAW_ANALYSIS.md](docs/CUTCLAW_ANALYSIS.md).

## 제품 원칙 (V1)

1. **타깃**: 일반 사용자 X, 주 3회+ 숏폼 제작 1인 크리에이터 O
2. **AI 심사 기준**: 스크롤을 멈추는 훅·캡션 — 무난하고 안전한 편집은 실패다
3. **속도**: 결과물이 나오기까지의 시간을 최소화 (아래 '속도 설계' 참고)
4. **추상적 요청 수용**: "재밌는 자막 넣고 눈에 확 들어오는 효과 넣어줘" 같은 프롬프트를 그대로 받는다. 캡션은 설명문이 아니라 반응·드립이어야 한다.
5. **출력**: 유튜브 쇼츠/릴스 표준 9:16 (1080×1920)

## 요구사항 매핑

| 기능 | 구현 위치 |
|---|---|
| 입력: raw video 1~3개 + 자유 프롬프트 | `app/api/routes.py`, `app/pipeline/ingest.py` |
| AI 핵심 추출 → 30~60초 숏츠 | `app/pipeline/highlight.py` → `screenwriter.py` |
| 자막 번인(메인스트림 스타일 normal/emphasis) | `app/pipeline/captions.py` + `render.py` |
| 무료버전 브랜딩: "directed by xlog" | `app/pipeline/outro.py` |
| 숏츠 form (LLM이 학습·갱신) | `app/knowledge/shorts_form.py` |
| A/B 2편 제작 + AI 심사 | `app/evaluation/judge.py` (기준: 스크롤 스톱, 캡션 밈) |
| 내 평가로 기준 학습 | `app/evaluation/feedback.py` → `rubric.py` (버전 관리) |
| **YouTube 링크로 스타일 학습** | `app/knowledge/reference.py` (yt-dlp + Claude vision) |
| 로컬 사이트 | `python run.py` → http://127.0.0.1:8321 |

## 속도 설계

- 프레임 분석: 전 영상의 청크를 **동시 병렬** LLM 호출 (`MAX_PARALLEL_LLM=4`)
- 원본 1개당 개략 스캔 프레임을 96장으로 상한 — 14분짜리도 LLM 호출 4회로 끝난다
- 렌더링 A · B를 **병렬** 실행. 심사는 렌더된 픽셀을 보므로 렌더 이후에 온다
- 심사와 교차 검증은 프레임을 **한 번만** 추출해 공유한다
- ffmpeg `veryfast` 프리셋, 자막 오버레이를 컷 인코딩과 같은 패스에서 처리

## 환각(hallucination) 방지 — 3중 방어

1. **결정론적 검증** (`app/pipeline/verify.py`): 편집안의 모든 컷 범위를 실제 영상 길이로 클램핑, 1초 미만·잘못된 인덱스 샷 제거 (LLM 아님, 코드)
2. **2단 분석**: 0.5fps 개략 스캔이 고른 구간을 2fps로 다시 읽어 비트를 좁힌다. 성긴 프레임에서 좋아 보였던 구간이 실제로는 빈 화면이면 여기서 탈락한다
3. **이중 심사**: Claude가 렌더된 픽셀을 심사하고 GPT(없으면 Haiku)가 같은 프레임으로 독립 심사 → 일치하면 "2모델 일치" 배지, 불일치하면 양쪽 추천을 모두 표시

교차 검증은 전부 **fail-open**. GPT 쿼터가 소진되면 그 실행 동안 OpenAI 호출을 끄고 Claude 검증 모델로 넘어간다.

## 취향 학습

Anthropic·OpenAI 셀프서브 파인튜닝이 모두 막혀 있어서 학습은 가중치가 아니라 **기준표(rubric)와 규칙**에 쌓인다. Claude가 매 선택마다 rubric을 개정하고, GPT는 검증만 한다.

1. **내 평가**: A/B 중 선택 + 코멘트 → Claude가 rubric을 개정 (기준 가중치·문구 조정 + 재사용 가능한 규칙 증류). AI 심사와 내 선택이 불일치하면 가장 강한 학습 신호로 강조됨
2. **레퍼런스 링크**: 좋아하는 숏츠의 YouTube 링크 + "왜 좋은지" 메모 → 다운로드 → 편집 스타일 역분석(훅 구성, 컷 리듬, 자막 사용) → 구체적 규칙으로 증류되어 rubric `preferences`에 병합

규칙은 무한히 쌓이지만 프롬프트에 들어가는 건 **재확인 횟수 상위 `XLOG_TASTE_RULES`개(기본 8)** 뿐이라 프롬프트 크기는 고정된다. 지금 무엇이 들어가는지는 사이트의 "학습 상태" 패널에서 그대로 볼 수 있다.

모든 rubric 버전은 `data/rubric/history/`에 스냅샷 보존. 레퍼런스 기록은 `data/rubric/references.jsonl`.

## 설치 및 실행

```bash
# 사전 조건: Python 3.11+, ffmpeg/ffprobe가 PATH에 있어야 함
cd xlog
pip install -r requirements.txt
# .env에 ANTHROPIC_API_KEY 설정 (이미 생성됨)
python run.py     # → http://127.0.0.1:8321
```

## 모델 라우팅과 비용

숏츠 1편 = LLM 호출 11회, 약 $0.97 (14분 원본 1개 기준). 비용의 대부분은 Opus의
**출력 토큰**(입력의 5배 단가 + effort에 따른 사고 토큰)이라, 모델보다 `effort`를
어디에 쓰는지가 값을 결정한다.

| 단계 | 모델 | effort | 이유 |
|---|---|---|---|
| 개략 스캔 (0.5fps) | Opus 5 | `medium` | 어느 구간을 정밀히 볼지 고르는 선별 작업. 고른 구간의 설명은 어차피 정밀 스캔이 덮어쓴다 |
| 정밀 재스캔 (2fps) | Opus 5 | `high` | 비트의 정확한 시작·끝. 이해도가 결과를 바꾸는 지점 |
| 편집안 A/B 작성 | Opus 5 | `high` | 서사 구성. 절대 낮추지 말 것 |
| 심사 · 기준표 학습 · 레퍼런스 | Sonnet 5 | — | 채점과 요약. sonnet-4-5보다 새롭고 33% 싸다 |
| 교차 검증 · form 갱신 | Haiku 4.5 / gpt-4.1-mini | — | confirm/reject 같은 기계적 JSON |

비용은 영상 길이가 아니라 **원본 개수**에 비례한다 (원본당 프레임 96장 상한).

## 로컬 전용

지금은 로컬 전용이다. Vercel 설정은 지웠다 — 60초 함수 상한, 휘발성 `/tmp`,
ffmpeg 부재 때문에 이 파이프라인을 담을 수 없었다. 나중에 배포한다면 필요한 것:
작업 큐를 처리하는 별도 워커, 영구 볼륨(또는 오브젝트 스토리지), ffmpeg 포함 런타임,
그리고 인증. 지금 API는 인증이 없고 `127.0.0.1` 바인딩이 유일한 방어선이다.

## 현재 한계 (다음 단계)

- 크롭이 센터 크롭 — 주체 인식(face-aware) 크롭으로 업그레이드 예정
- "효과"는 자막 2종만 — 줌/펀치인·트랜지션·사운드 이펙트는 다음 단계
- ASR(음성 인식) 미연동 — 대사 기반 모먼트 추출·자막 싱크는 다음 단계
- 레퍼런스 학습은 1fps 프레임 기반 근사 — 정밀 컷 감지(scenedetect)는 다음 단계
- 동시 작업 미지원 — `job.json`에 잠금이 없고 `reclaim()`이 작업 간에 공유된다
